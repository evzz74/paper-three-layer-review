# L2 核查操作手册

本文件是 SKILL.md 第 4 节与第 5 节的展开细则。写 L2 时逐步对照，不要凭印象打分。

## 1. 证据强度 A–D 分级

| 级别 | 定义 | 典型形态 |
|---|---|---|
| **A 直接证据** | 断言与测量对象一致，且实验设计能排除主要替代解释 | 随机对照实验、预注册分析、统计功效足够的样本、多种子 + 误差棒 + 显著性检验 + 效应量；消融定位到具体组件 |
| **B 强间接** | 主结论有对照且基线公平，但缺机制检验或跨设定复现 | 有对照组与消融，单数据集但基线调参预算对齐；跨数据集复现但只跑一次超参；结论方向稳定但机制只能推测 |
| **C 弱间接** | 存在系统性替代解释，或测量与断言错位 | 单数据集单种子、无误差棒、基线未公平调参、只用代理指标、结论依赖某个未说明的数据清洗步骤、相关性被写作因果 |
| **D 无证据 / 反向** | 不足以支撑任何断言，或数据方向与断言相反 | 无对照、循环论证、样本量不足以支撑该强度断言、只引用他人结果、原文数字与结论矛盾、选择性报告 |

判定时必须写一句「为什么是这个级别」，并**指名缺哪一项**：样本量 / 误差棒 / 重复种子 / 对照组 / 基线调参 / 指标效度 / 跨设定复现。只写"A 级"不写理由的，视为未完成核查。

同一条结论在正文与附录可得信息不同时，按**较弱**的一侧定级（保守原则）。

## 2. 五类成立前提（逐条问，不许跳过）

**2.1 数据前提**
- 样本是否代表目标总体？抽样方式是什么？有无选择偏差、幸存者偏差、标注者偏差？
- 训练/验证/测试切分是否防泄漏？时间、用户、实体层面有没有重叠？
- 数据规模是否足以支撑所声称的效应大小？

**2.2 分布与独立性假设**
- 是否假设 i.i.d.？实际数据是否违反（时间相关、聚类、重复测量）？
- 是否假设训练与部署同分布？有没有做过分布漂移检验？
- 统计检验的假设（正态、方差齐、独立）是否被检验过？

**2.3 实现与超参前提**
- 关键超参是搜索得到还是默认值？搜索空间多大、预算多少？
- 结果对随机种子、初始化、批大小的敏感度是否报告？
- 复现门槛：代码、数据、环境是否公开？缺哪一项？

**2.4 评测前提（最常被跳过的一类）**
- 指标是否真的测到了它声称的东西？代理指标与目标效用之间的映射有没有被验证？
- 指标是否可被"刷"（Goodhart 风险）？有没有对抗性检验？
- 显著性检验是否匹配多重比较？置信区间是单次运行还是跨种子？
- 人类评测的话：标注者是谁、一致性多少、指导语是否泄露预期？

**2.5 范围前提**
- 模型规模、领域、语言、时间窗、人群、硬件条件——结论在这个范围内成立，超出即外推。
- 逐项写清"本文覆盖到哪、没覆盖到哪"，这是第 5 问的直接输入。

## 3. 三项横向检查

### 3.1 数字自洽
- [ ] 同一数字在摘要 / 正文 / 表格 / 图中是否一致（逐个比对，列出差异）
- [ ] 百分比基数是否写明（分母是谁）
- [ ] 涨跌幅是绝对值还是相对值，表述是否混淆
- [ ] 显著性标记与所用检验是否匹配；多重比较是否校正
- [ ] 误差棒含义是否写明（std / sem / 95% CI / 跨种子）
- [ ] 表格中最佳值是否按同一指标选出（有无跨列混排）

### 3.2 基线公平
- [ ] 算力、数据量、训练时长是否对等
- [ ] 基线是否用了作者的实现而非原版（重实现常被削弱）
- [ ] 基线是否做了同等强度的调参；只用默认值即宣布超越 → 标 `稻草人基线`
- [ ] 是否遗漏了更强的同期基线（尤其是投稿前半年内的）
- [ ] 是否只在对自己有利的指标/子集上比较

### 3.3 消融完整性
- [ ] 每条声称的贡献是否有对应消融（逐个贡献点名核对）
- [ ] 消融是否只删不加（缺"只留该组件"的正向对照）
- [ ] 组件间是否存在交互效应未拆解
- [ ] 缺的消融是否被写成"未来工作"来回避

## 4. 越界判定句式

L2 结尾必须二选一，不许含糊：

**判定为越界**
> `C{k}` 的断言「<逐字原话>」超出其证据：证据只支持「<数据实际显示>」（`[事实]`，位置 X），而断言额外要求「<外推/因果/机制/泛化/价值判断>」（缺的那一步：___）。越界类型：外推 / 因果 / 泛化 / 机制 / 价值。

**判定为未越界**
> 未发现越界。逐条核对：证据「<锚点>」→ 断言「<原话>」之间的推论链完整，替代解释已被 <对照/消融/检验> 排除，范围为 <写明>。

五种越界类型：
- **外推越界**：从受控设定推向真实场景
- **因果越界**：从相关/干预不足推出因果
- **泛化越界**：从单一数据集/领域/语言推向通用
- **机制越界**：从性能提升推出机制成立（benchmark 提升 ≠ 机制被证明）
- **价值越界**：从指标提升推出"更有用/更好"

## 5. 缺口四分类判定

| 类别 | 识别信号 | 记录格式 |
|---|---|---|
| 作者自认局限 | Limitations / Discussion 中的自述 | `G-A{n} | 原话（锚点）| 本文是否给出缓解` |
| 作者未意识到 | L2 中 `未检验` 的反证条件、稻草人基线、指标错配、跳步 | `G-B{n} | 问题 | 由哪条 C/L2 项暴露` |
| 方法固有边界 | 换设定即失效（规模、模态、语言、硬件、时延） | `G-C{n} | 边界 | 触发条件 | 失效表现` |
| 领域空白 | L0 的 `GAP`/`LIM` 中本文未触及项 | `G-D{n} | 空白 | 依据 | 与本文相邻关系` |

只写第一类（作者自认）是最常见的偷懒；第 2、3 类才是审读的增量价值。

## 6. 假设卡质量线

- **陈述**必须含方向与可测对象。合格：`在长尾查询上加入检索增强会使召回率提升且不显著增加时延`。不合格：`未来可以研究检索增强`。
- **依据**必须指回具体编号（`GAP` / `LIM` / `C` / 跳步编号），不能写"直觉上"。
- **设计**必须给出最小可行实验：数据从哪来、对照组是谁、要几个种子、算力预算量级。
- **判别**必须双向且可观测：
  - 支持 = 具体阈值（如"召回率 +≥3 个点，p<0.05，3 种子一致"）
  - 否定 = 具体阈值（如"提升 <1 个点，或时延增幅 >20%"）
  - 写不出两侧 → 假设未成形，退回重写。
- **至少一张卡是证伪方向**：设计一个能让作者结论失效的实验（换分布、换基线、加对照、扩大样本），并写明"若结果如此，则 C{k} 应被降级为 ___"。
